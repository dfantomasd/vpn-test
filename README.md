Независимый каталог подписок для Happ и Karing. Для использования не требуется
запускать Python или держать компьютер включённым.

## Happ на iPhone

Скопируйте ссылку целиком, откройте Happ → «+» → импорт из буфера обмена:

```text
https://raw.githubusercontent.com/dfantomasd/vpn-test/main/subscription.txt
```

Файл — родной для Happ **JSON-массив полных Xray-конфигураций**, а не список
преобразованных ссылок. Первым идёт **«🔄 Авто»**, далее — отдельные серверы.
Авто собирается из допущенных зарубежных одиночных VLESS-профилей без изменения
их параметров подключения. На устройстве burstObservatory выполняет HTTPS-пробы
примерно раз в минуту (два измерения, тайм-аут 3 секунды), leastLoad выбирает
выход для новых соединений. Существующее соединение не переносится бесшовно.
Если все проверки неудачны, ядро пробует первый выход; это не гарантирует связь.
Скорость скачивания на устройстве не измеряется, работа Telegram пробой не доказана.

Выберите «🔄 Авто» вручную. Оставьте «Без сортировки». Для проверки отключите
«Подключать при запуске → Мин. задержка», чтобы Happ не выбирал другой профиль.
Профили «Скорость» и «Авто недоступен — резерв» больше не публикуются.

Правила России встроены в каждый JSON-профиль, отдельный пункт Russia в меню
Happ может не отображаться. Telegram (домены и GeoIP) имеет приоритет через VPN;
российские домены, IP и локальные сети — напрямую; остальные соединения — VPN.
Для неизвестных доменов выполняется второй проход по IP (`IPIfNonMatch`):
итоговое правило охватывает IPv4/IPv6, а не все сети без условий, поэтому
российский IP может попасть в direct даже без домена в списке. Это добавляет
DNS-проверку неизвестных доменов и не гарантирует ускорение каждого приложения.
Общий запрет UDP/443 и обход VPN для BitTorrent удалены.

DNS разделён: домены из списка прямого доступа разрешаются через базовый
Яндекс DNS (77.88.8.8 и 77.88.8.1) по TCP напрямую, вне VPN. Эти DNS-запросы
не шифруются; их могут видеть сеть и DNS-провайдер. HTTPS-трафик приложений
при этом остаётся зашифрованным. Остальные DNS-запросы идут через VPN к Google DoH.
Домашние резолверы не используются как запасные для зарубежных доменов;
если оба прямых DNS недоступны, запрос российского домена завершится ошибкой,
а не уйдёт через зарубежный сервер. Доступность и задержку проверяйте на iPhone.

Для Karing скорость оценивается медианой трёх скачиваний по 256 КиБ.
Замеры старше 6 часов не используются для рейтинга при сборке.
При полной остановке GitHub файл сам измениться не может — проверяйте дату.
Неудачный тест с GitHub не доказывает недоступность сервера на iPhone.

Неподдерживаемые конвертером Karing узлы пропускаются и перечисляются в отчёте,
не блокируя Happ. Их сетевые замеры тоже пропускаются. Если для Karing не
осталось поддерживаемых узлов, сохраняется предыдущий файл с явной отметкой
`karing_publication` в отчёте; он может содержать устаревшие данные.

Узлы без подтверждённой страны регистрации исключаются. Если осталось меньше
двух допустимых одиночных профилей, новая публикация отменяется и сохраняется
предыдущая подписка: одиночный сервер не выдаётся за автовыбор.
GeoIP и регистрация сети — эвристики, не гарантия физического расположения.

Перед публикацией каждую Happ-конфигурацию проверяет Xray (`run -test`),
без подключения VPN. Это не заменяет проверку в Happ на iPhone.

Встроенные правила каждой JSON-конфигурации направляют российские домены напрямую,
а остальной трафик через выбранный профиль. Обновление файла на GitHub запланировано
раз в час (запуски могут задерживаться); автообновление самой подписки в Happ
настраивается в приложении.

## Karing на iPhone

Экспериментальные узлы не добавляются ни в эту подписку, ни в основной Happ.

Добавить конфигурацию → по ссылке:

```text
https://raw.githubusercontent.com/dfantomasd/vpn-test/main/subscription_karing.txt
```

Это **Clash YAML**, несмотря на расширение `.txt`: в отличие от списка VLESS,
он содержит правила маршрутизации, а не только серверы.

ВАЖНО: Karing не позволяет принудительно переключить все локальные настройки
одной подпиской. При добавлении включите **«Сохранить правила перенаправления
провайдера» / Keep ISP diversion rules**. В разделе правил выключите
**«Отключить правила перенаправления [ISP]» / Disable ISP diversion rules**.
Названия могут отличаться между версиями. Выберите режим **Правила / Rule**,
не Global, и сервер в группе VPN_BEST. После изменения переподключитесь.
Первый пункт группы — **«🏆 Автовыбор на устройстве»**: он выбирает сервер
по задержке с вашего устройства. Выберите его для автоматического режима.
Для уже импортированной подписки с потерянными правилами добавьте её заново,
включив сохранение правил.

Karing управляет DNS внутри приложения: секция DNS из Clash-подписки не применяется.
Для direct используйте доступный локальный DNS, для proxy — DNS через туннель;
обновите приложение, если отдельных настроек DNS/правил нет.

## Маршрутизация Russia

- Прямой маршрут: `.ru`, `.su`, `.рф`, список `category-ru`, дополнительные
  российские банковские/государственные домены, российские IP и локальные сети.
- По умолчанию весь остальной трафик идёт через выбранный VPN-сервер.
- Отдельный список «только заблокированных зарубежных сайтов» не используется:
  иначе нельзя надёжно определить, какой новый зарубежный сервис требует VPN.
- Зарубежные проверки IP (`ipinfo.io`, `ifconfig.me`, `browserleaks.com` и другие)
  больше не имеют старого принудительного direct-исключения. `2ip.ru` остаётся direct
  как российский домен. Встроенный iCloud Private Relay может менять результат проверки.
- Название **Russia** относится к правилам обхода, а не к стране VPN-сервера.

Полного и вечного списка всех банков, порталов и их CDN не существует: геобазы
могут ошибаться, новые домены могут отсутствовать. Если конкретный сервис не работает,
нужны домен и журнал маршрутизации для добавления точного исключения.
При полном отсутствии связи правила не восстанавливают доступ оператора.

## Без российских VPN-серверов

Из **обеих новых подписок** исключаются узлы с названием Россия/Russia/🇷🇺,
а также входные IP, попадающие в российские диапазоны GeoIP или имеющие
российскую регистрацию сети в RDAP (RIPE/региональные реестры).
Для доменных имён сохраняются результаты DNS-проверки; неразрешимые имена
исключаются, а не считаются зарубежными. GeoIP определяет входной адрес,
но не доказывает фактическую страну выхода или владельца инфраструктуры.
При изменении DNS/геобазы нужна пересборка.

В обе подписки экспортируются **только VLESS-узлы**. Для Happ сохраняются полные
нативные профили. Если внутри составного профиля есть другой протокол, российский
или неопределённый входной узел, профиль исключается **целиком**: внутренние цепочки
и балансировщики не редактируются частично. Количество актуальных профилей/узлов
указано в `build_report.json`. XHTTP-узлы требуют актуальной
версии Karing и проверки на устройстве.
При будущих обновлениях неподдерживаемые расширенные XHTTP-параметры могут приводить
к исключению узла из Karing с записью причины в отчёт, а не к тихой потере настроек.

Полный отчёт исключений: [build_report.json](build_report.json).
Старый `whitelist_configs_combined.json` — исходный снимок, НЕ новая подписка:
в нём оставлены оригинальные записи, включая российские; не импортируйте его
для этих требований. Экспорт раскрывает балансировщики в отдельные узлы,
не переносит их алгоритм автоматического выбора, QUIC-блокировку и direct для BitTorrent.

## Независимость и безопасность

Репозиторий не обращается к kenkaral45 для обновлений. Сохранён снимок конфигураций,
но серверы и ключи в нём принадлежат сторонним операторам и могут перестать работать.
Это не собственная VPN-инфраструктура и не подтверждение прав на чужие серверы.
Используйте только доступ, на который у вас есть разрешение.

Каталог открыт всем. НЕ добавляйте сюда личные ключи или платные приватные подписки.
GitHub Secret скрывает URL источника, но НЕ содержимое опубликованного JSON:
сгенерированные ключи будут доступны публично и сохранятся в истории Git.

## Обновление

В этом репозитории включено обновление **из Liberty каждый час**, в 17-ю минуту
часа (GitHub может задерживать запуск). Ссылка хранится в GitHub Secret, а не в коде.
Параметры владельца:

1. Settings → Secrets and variables → Actions → Secret `SUBSCRIPTION_URL`:
   свой разрешённый HTTPS-источник с JSON-конфигурациями Xray.
2. Actions → Variable `ENABLE_SUBSCRIPTION_REFRESH` = `true`:
   подтверждение, что полученные конфигурации разрешено публиковать открыто.

После настройки можно запустить Actions → Subscription → Run workflow.
Формат источника: непустой JSON-массив объектов с remarks, outbounds и routing
либо HTML с такими JSON-объектами. Обычные списки vless:// и Base64 не поддерживаются.
После обновления исходного каталога workflow пересобирает обе подписки,
обновляет публичные геоданные, повторяет фильтрацию российских входных узлов,
проверяет соединения и выполняет ограниченный замер скорости.
При ошибке загрузки/генерации старые опубликованные файлы остаются на месте.
Happ получает геофайлы по ссылкам профиля из Loyalsoldier.

### Отдельная экспериментальная подписка Happ

`subscription_experimental.txt` — отдельный небольшой список новых VLESS-узлов
из трёх независимых кандидатов: сначала igareck (проверяет из России), затем
Au1rxx (HTTP/TLS-проверки), затем morpheusadam (большой резервный каталог).
Рабочие `subscription.txt` и `subscription_karing.txt` не изменяются этим процессом.
Ссылка для импорта:

```text
https://raw.githubusercontent.com/dfantomasd/vpn-test/main/subscription_experimental.txt
```

Каждому источнику выделено до восьми мест для проверки, чтобы большой каталог
не вытеснил остальные. Первый этап принимает только TCP + TLS/REALITY, UUID и
публичный IP либо разрешимое доменное имя сервера.
Неизвестные параметры, небезопасный TLS, российские и неопределённые страны,
а также адреса из рабочего каталога исключаются. Проверяются максимум 24 узла,
публикуются до 10 прошедших тест скачивания, в порядке измеренной скорости.
Минимум для публикации: 1,5 Мбит/с и не более 1500 мс в проверке GitHub.
Полные профили содержат те же правила России, Telegram и разделение DNS.
Это ручной выбор, не ещё один автоматически рекомендуемый «лучший» сервер.

Источник замеров и время указаны в `experimental_report.json`. Проверки с
компьютера или GitHub не гарантируют скорости или доступности Telegram на iPhone.
Публичные серверы не проверены на добросовестность владельца.
Если успешных узлов нет, предыдущая экспериментальная подписка сохраняется.

Обновление пока только вручную: Actions → Experimental VLESS → Run workflow.
Нет автоматической подмешки в рабочий «Авто» и нет отдельного почасового запуска.
White-List-VPN не используется: он ориентирован на российские входные адреса.

### Что означают цифры

- В Karing **«тест GitHub: ≈… Мбит/с · … мс» в названии** — внешняя проверка с GitHub Actions.
  Это не скорость вашего iPhone. Недоступные результаты: **«нет замера»**.
- **Пинг рядом с сервером в приложении** — замер самого телефона, используемый
  для локальной сортировки/автовыбора. Он меняется при смене Wi-Fi/мобильной сети.
- В Karing узлы упорядочены по внешнему рейтингу: `Мбит/с / (1 + задержка_мс / 200)`.
  Это эвристика, не универсальное определение лучшего сервера. В Happ первый
  профиль — настоящий автовыбор на устройстве, далее — ручной выбор сервера.
- Скорость измеряется медианой трёх коротких загрузок по 256 КиБ, поэтому
  является приблизительной, а не полноценным Speedtest. Задержка — HTTPS TTFB,
  включая установление соединения, не ICMP ping. До примерно 15 МиБ за запуск на 20 узлов
  плюс служебный трафик. Эти проверки расходуют трафик VPN-серверов и минуты GitHub Actions.
- Внешние результаты и время проверки доступны в `measurements.json`.

Локальная проверка без сети:

```sh
python3 -m unittest discover -s tests -v
SUBSCRIPTION_SOURCE_FILE=whitelist_configs_combined.json python3 scripts/refresh_subscription.py
python3 scripts/build_clients.py
python3 scripts/build_clients.py --check
```

Обновить геоданные и DNS-снимок (требуется интернет):

```sh
python3 scripts/build_clients.py --refresh-rules
```

## Проверка на телефоне

1. Импортируйте соответствующую новую ссылку и проверьте активность правил.
2. Проверьте Сбер/Т-Банк/Госуслуги: в журнале соединений ожидается DIRECT.
3. Проверьте YouTube и зарубежный сайт IP: ожидается VPN/выбранный сервер.
4. Повторите на Wi-Fi и мобильной сети. Один значок VPN не доказывает работу.

Локально проходят 27 тестов, проверка YAML и проверка конфигурации Mihomo `-t`.
Внешние сетевые пробы НЕ заменяют проверку импорта/соединения в iOS Happ/Karing.
